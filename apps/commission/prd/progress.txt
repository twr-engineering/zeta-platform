## Bugs found and fixed during that verification
- app.is_workspace_member() referenced public.membership before it existed; SQL-language
  function bodies are validated at CREATE time, so the first `db push` would have failed.
  Predicates moved into the workspace/membership migration, after the tables.
- audit_log_entry.actor_user_id had ON DELETE SET NULL, which is an UPDATE — the append-only
  trigger rejected it, deadlocking account deletion. It also erased *who acted*. Now a bare
  uuid with no FK, pinned to auth.uid() by RLS.
- Deleting a user stranded the workspace, tax_settings and audit rows (nothing links
  workspace → auth.users), leaving unreachable financial data and breaking M0.4's
  data-ownership guarantee. Added app.reap_orphaned_workspace() on last-member-out.
