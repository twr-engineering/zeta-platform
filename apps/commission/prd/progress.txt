STREAMING-vs-BUFFERED, THE DECISION (documented in the route header, per team-lead ask): a DEDICATED route
`/api/export/search` (GET-only), NOT a new entry in the buffered `/api/export/[dataset]` registry. Why:
(1) the search set is filter-parameterized by the whole SearchQuery (year asymmetry, normalized text,
status/balance, sort matrix) and its columns are the §3.2 projection — threading that through the registry's
`DealExportFilters` would fork it; a source route reusing the same `runSearch` the SCREEN uses keeps the
download tied to the screen (AC11). (2) CSV genuinely STREAMS — a ReadableStream emits the header then pages
the RPC in bounded 1,000-row batches, flushing each as it arrives → peak memory is one batch, so an uncapped
set (OQ4 default = no cap) cannot blow the heap. (3) XLSX is BUFFERED because the format demands it
(`write-excel-file` builds a zip whose central directory needs every row before byte 1 — there is no streaming
XLSX); it is fed from the SAME bounded pager, so the DB is never asked for an unbounded single result, and at
the 2,000-row design target the peak is ~1–2 MB, well within limits. MEASURED: 2,000-row export end-to-end
1.89 s (CSV assemble 4 ms, XLSX 64 ms; paging over WAN dominates) — comfortably < the 10 s NFR. So the PRD's
"streams (no full materialization)" is honoured for the unbounded case (CSV) and the buffered path is a
documented, format-forced exception that is negligible at scale.

## Rate limiting / hardening — native vs added (M0 §8, FR of M0.4 hardening pass)
  What Supabase/GoTrue provides NATIVELY (server-side, not something we implement):
    - Auth endpoints are rate-limited by GoTrue: sign-in / sign-up / token refresh / OTP /
      password-recovery / verify all have per-IP and per-window limits (configurable in the
      dashboard). Email sending is separately rate-limited (this is M0.1's SMTP blocker).
    - Passwords are bcrypt-hashed by GoTrue; sessions are JWT + rotating refresh tokens.
  What M0.4 ADDED:
    - Session invalidation on password change (global signOut) — the §8 requirement.
    - Current-password re-authentication before password AND email change, which also means
      those actions ride GoTrue's rate-limited signInWithPassword rather than being an
      unthrottled side door.
    - Security response headers (next.config.ts headers()): X-Frame-Options DENY,
      X-Content-Type-Options nosniff, Referrer-Policy strict-origin-when-cross-origin,
      Permissions-Policy (camera/mic/geo/topics off), HSTS (inert on localhost, live on
      Vercel), and a CSP of frame-ancestors 'none' / base-uri 'self' / object-src 'none' /
      form-action 'self'. Deliberately NO default-src or script/style CSP: default-src would
      fall through to connect-src and block the browser Supabase client + Next HMR socket, and
      a nonce-based script CSP is a documented follow-up (see gaps).
    - Deletion is service-role + typed-confirmation + own-id-only; the whole-workspace export
      and every account read are RLS-scoped with no id in any URL.

## Bugs found and fixed during M0.1 browser verification (all pre-existing, none caught before)
- P0 — THE ACCOUNT MENU NEVER OPENED, so sign-out was unreachable from the UI entirely.
  src/components/layout/app-header.tsx put DropdownMenuLabel directly inside
  DropdownMenuContent. That label is Base UI's Menu.GroupLabel, which throws
  "MenuGroupContext is missing" outside a Menu.Group; the throw killed the popup's whole
  render, so nothing appeared. Fixed by wrapping it in DropdownMenuGroup. This is exactly
  the class of bug a browser catches and a build never does — the foundation's own report
  flagged "no end-to-end browser signup/login yet" as the gap, and this was hiding in it.
- Page titles under /settings lost the root's "%s · ZETA GCI + Collections" template (tab
  read "General"). A plain `title` on the settings layout displaces the template for its
  children; removed it, since each section page sets its own title.
- Playwright's default 5s expect timeout is shorter than a cold `next dev` route compile
  (a first server action measured ~2s, more on a cold start), which produced e2e failures
  that looked like app bugs but were the harness racing the compiler. playwright.config.ts
  now sets expect.timeout to 15s.

## Footguns closed (these cost real time — do not reintroduce)
- `pnpm run build` while the dev server is running CORRUPTS ITS .next AND KILLS IT — both
  write to the same directory. Use `pnpm run build:check` (NEXT_DIST_DIR=.next-build) for
  any verification build. `pnpm run build` stays as-is for Vercel.
- The dev server watches the project root, and its ignore list is only node_modules/.git/
  .next. `.playwright-mcp/` gets a page snapshot + console log written on EVERY browser
  tool call, which drove the dev server into a permanent recompile loop and stalled
  in-flight requests. next.config.ts now extends webpack watchOptions.ignored to cover
  .playwright-mcp, .next-build, test-results and playwright-report. NOTE: that hook does
  NOT run under `next dev --turbopack`, and Turbopack has no exclusion option — if dev
  moves to Turbopack these dirs must move outside the project root instead.

## CRITICAL finding from live verification — PostgREST returns numeric as FLOAT
`select("*")` on tax_settings returned `ewt_rate: 0.1` (a JSON number -> IEEE-754 double)
and even dropped scale (`3600000`, not `3600000.00`). That is a binary float in a money
path, which Master PRD §4.3 forbids outright, and `supabase gen types` types these columns
`number`, baking the mistake into the types.
Fix (in place, verified live):
- Money/rate columns are selected with a `::text` cast -> "0.1000" / "3600000.00", exact
  and scale-preserved. Selects live in src/lib/supabase/selects.ts. NEVER `select("*")` on
  a table carrying money.
- Types are layered so regeneration cannot silently reintroduce the float:
    src/types/database.generated.ts  machine-generated, do not edit
    src/types/database.ts           money-safe override (numeric -> string), audit Update: never
    src/types/entities.ts           named row aliases
  A tsc assertion confirmed a float rate fails to typecheck.
- End-to-end: rates fetched from the LIVE db reproduce the PRD's ₱50,000 Inclusive split
  (GCI 44,642.86 / EWT 4,464.29) exactly.
M1/M4/M5 MUST add their `::text` selects + overrides when they add money tables.
